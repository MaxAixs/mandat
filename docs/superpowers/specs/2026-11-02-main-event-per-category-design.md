# Головна новина в кожній категорії — дизайн

Дата: 2026-11-02. Статус: чернетка, чекає затвердження.

## Навіщо

Зараз прапор `main_event` глобальний: максимум одна опублікована головна
новина на весь сайт (частковий унікальний індекс `idx_news_single_published_main_event`
з міграції `00007`, плюс проактивне зняття прапора з усіх інших у
`withPublishedFlagsLock`). Редакції цього мало: кожна рубрика
(«Новини», «Міжнародні новини», «Спорт», «Інтервʼю», «Про нас») повинна мати
власну головну новину, яка показується великим блоком на сторінці категорії,
а на головній сторінці лишається спільна стрічка всіх новин плюс одна
головна новина.

## Цілі

1. У кожній категорії рівно одна головна новина (серед опублікованих).
2. Вибір нової головної знімає прапор з попередньої тільки в цій категорії;
   інші категорії не чіпаються.
3. Міграція `00008_main_event_per_category.sql`: прибрати глобальний індекс
   `idx_news_single_published_main_event`, створити унікальний індекс по
   `(category)` для `status = 'published' AND main_event = TRUE`.
4. `internal/repository/postgres/news.go`: очищення попередньої головної
   новини лише в межах тієї ж категорії (та ж техніка: блокування таблиці +
   проактивний UPDATE, унікальний індекс як страховка від гонок).
5. Адмінка `NewsEditorDialog`: перемикач «Головна новина категорії» замість
   «Головна подія дня».
6. Сторінка категорії: головна новина цієї категорії — великим блоком зверху,
   решта — як зараз (сітка + пагінація + стрічка «Останні новини»).
7. Головна сторінка: без змін структури — спільна стрічка всіх новин плюс
   Hero-блок з однією головною новиною: найновішою `main_event` серед усіх
   категорій (за `published_at`). Якщо жодної головної немає, Hero ховається,
   як зараз.

## Не-цілі

- Кілька головних новин в одній категорії; заплановані головні; головні
  серед чернеток (обмеження діє лише для `status = 'published'`, як зараз).
- Зміна логіки прапора `featured` — він лишається глобальним.
- Зміна форм публічного API: поле `main_event` у відповідях лишається,
  нових ендпоїнтів не потрібно (списки вже повертають прапори).
- Редизайн Hero і карток: використовуємо існуючі компоненти і стилі.

## Анти-цілі

- Вибір головної в одній категорії мовчки знімає головну в іншій.
- Порушення інваріанта «одна головна на категорію» при паралельних запитах
  (гонки мають ловити індекс + транзакційне очищення, а не надія на удачу).
- Чернетка або видалена новина лишається «головною» видимою десь на сайті.

## Обмеження

- Бекенд: Clean Architecture, SOLID, `AGENTS.md` (константа `fc` у функціях
  сервісу/репозиторію, sentinel-помилки в `internal/errs`, класифікація
  помилок без деталей всередину, логування тільки в сервісному шарі,
  goose-міграції, параметризовані запити).
- Фронтенд: `frontend/AGENTS.md` (`npm run lint` і `npm run build` зелені,
  класи тільки `mandat-*`, без правок `components/ui`, контент не живе
  в компонентах).
- Маршрутизація робіт: тести пишуть `test-author`, ревʼю робить `reviewer`;
  основна сесія тестові файли не чіпає. Коміти і пуші — тільки за явною
  командою.
- Прапор `main_event` для фронтенда вже приходить у публічних відповідях;
  окремого ендпоїнта «головна новина категорії» не вводимо.

## Що вже вирішено

- Унікальність: частковий унікальний індекс `(category)`
  `WHERE status = 'published' AND main_event = TRUE`; стара глобальна
  умова зникає разом з індексом.
- Ротація: вибір нової головної = транзакція, що гасить прапор попередній
  головній тієї ж категорії і ставить новий; конкурентна вставка ловиться
  індексом і мапиться в `ErrConflict`, як зараз.
- Текст перемикача в редакторі: «Головна новина категорії».
- Великий блок категорії: перевикористати стиль featured-картки
  (`NewsCard` з `lg:col-span-2`), без нових компонентів.
- Hero головної: найновіша опублікована `main_event` серед усіх категорій.

## Вирішено за замовчуванням (перевірити при читанні)

- Down-міграція `00008` відкочує індекс назад до глобального; дані, де в
  різних категоріях є свої головні, при відкоті порушать старий індекс —
  це прийнятно для dev-відкоту, на проді відкотів без ручної чистки не буде.
- Зняття з публікації / видалення головної просто звільняє слот категорії;
  окремої «запасного» механізму немає.
- Порядок «найновіша» для Hero — за `published_at DESC` (NULLS LAST, як
  у списках).

## Рішення після перевірки білдером (затверджено)

- Дублювання: головна новина лишається і в сітці/стрічці під великим блоком
  (статус-кво, як Hero на головній зараз); пагінація не чіпається.
- Великий блок категорії: новий опційний презентейшн-проп `NewsCard`
  (напр. `size`), без підміни `featured` у даних (моє рішення, дрібне).
- Hero головної: найновіша `main_event` з першої сторінки публічного списку
  за `published_at DESC`; припускаємо, що перша сторінка (ліміт 20) містить
  усі головні (категорій — 5).
- Ротація при зміні категорії в одному збереженні: гасимо слот нової
  (збереженої) категорії; стара лишається вакантною.
- Міграція вгору без авточистки: дублікати в межах категорії валять міграцію
  з помилкою, чистка вручну перед деплоєм.
- Прапор `main_event` на чернетці/знятій з публікації зберігається;
  ротація спрацьовує в момент публікації.

## Лишено білдеру (план і код)

- Точні назви функцій/полів, структура транзакції в репозиторії, обробка
  `ErrConflict` у сервісі при гонці.
- Як сторінка категорії отримує головну: окремим вибором з уже
  завантаженої сторінки списку чи першим елементом; що робити, коли головна
  на 2+ сторінці пагінації.
- Мапінг `main_event` у фронтенд-тип `Article` (зараз `toArticle` його не
  несе) так, щоб тести `test-author` оновив коректно.
- Набір тестів: Go (репозиторій/сервіс/мапінг помилок) і фронтенд
  (мапінг API, Hero, сторінка категорії) — пише `test-author` до коду.
- Порядок білда за планом; ревʼю — `reviewer` після зеленого `go test ./...`,
  `npm run lint`, `npm run build`.
